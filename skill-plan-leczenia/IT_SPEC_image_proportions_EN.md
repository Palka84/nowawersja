# IT specification – tooth images in the treatment-plan chart (proportions)

Audience: the IT team building the Fly4Smile treatment-plan system.
Goal: the tooth chart generated by the system must look exactly like the charts in Fly4Smile's own offers – one common scale, teeth touching each other like real teeth, full-arch prostheses occupying exactly the place of the teeth they replace.

Reference material (Google Drive folder "Proporcje na planie leczenia – zgłoszenie 2026-11-25"):
https://drive.google.com/drive/folders/1dXW8p5hUMjujChU0zczYVGSgP3846RFV
- `BLAD_proporcje_zrzut_z_planu.png` – current system output (wrong)
- `POPRAWNIE_jedna_skala.png` – the same case drawn correctly
- `TEST_krzyzowy_oferta_vs_system.jpg` – cross-check on 6 plans: left = Fly4Smile offer chart, right = the same plan built from the normalized images with plain HTML/CSS (the approach described below)
- `normalizuj_rysunki_v3.py` – script that converts the image library to the format below

## 1. What is wrong today

The system places each image into one of 16 equal-width cells per row and fits it with `object-fit: contain`. The library images are tightly cropped, so every image gets a different scale: pontics look huge, incisors tiny, and a full-arch image (`12_zirconia_crowns_upper_all-on-6.png`) is stretched across 11 cells and becomes several times larger than the neighbouring teeth. Equal-width cells also leave gaps between teeth.

## 2. Image library (new version, prepared by the graphics team)

All drawings keep one common scale: **32.7 px = 1 mm** (Wheeler anatomical dimensions). Drawings are never rescaled – only placed on a transparent canvas:

| Element | Canvas height | Canvas width | Placement |
|---|---|---|---|
| Single tooth / crown / crown on implant / temporary crown / pontic / veneer / extraction / natural tooth | **940 px** (all files) | **tooth-position width** from the table below | centred horizontally |
| Implant without crown (`implant_XX`, `zirconia_implant_XX`) | 940 px | tooth-position width | implant platform 265 px from the occlusal line |
| Full arch (`*_all-on-4/6`) | 940 px | sum of position widths 16–26 (upper) or 46–36 (lower) | centred |
| Missing tooth (`missing_XX.png`, new) | 940 px | tooth-position width | fully transparent |

Vertical alignment:
- **Upper jaw** (FDI 1x, 2x; primary 5x, 6x): occlusal edge of the crown **30 px above the bottom** of the canvas, roots pointing up.
- **Lower jaw** (FDI 3x, 4x; primary 7x, 8x): occlusal edge **30 px below the top** of the canvas, roots pointing down.

Tooth-position width (px, on the 940 px-high canvas) = width of that tooth's zirconia crown + 4 px on each side:

## 3. Rendering in the system (the only required change)

Do **not** use equal-width cells. Render each row as a flex row in which every image has the **same height** and **automatic width**:

```css
.row      { display:flex; justify-content:center; gap:1px; }
.row.up   { align-items:flex-end; }     /* upper jaw */
.row.lo   { align-items:flex-start; }   /* lower jaw */
.row img  { height:96px; width:auto; }  /* 96 px fits a full row on a 520 px-wide mobile page */
```

- One column per tooth: tooth number + image (number above the image in the upper row, below it in the lower row).
- Missing tooth: put `missing_XX.png` in its place so the gap stays and neighbouring teeth do not shift.
- Full arch: one column containing the arch image; the tooth numbers 16–26 (or 46–36) above/below it are distributed proportionally to the widths in the table (not evenly).

Because every file has the same height, every element gets the same scale factor – proportions are correct and teeth touch like in the offers. Working example: `przyklad_system/schemat_przyklad.html` in this repository (open in a browser).

## 4. Things the images cannot do – the system must draw them

1. **Bridge connector** – a rounded bar behind the crowns from the first to the last tooth of a bridge, in the crown colour (turquoise; for temporary work amber `#E2AA5A`).
2. **Number of a missing tooth** – grey and struck through.
3. **Highlighted numbers** – teeth treated in the given visit get the number in a turquoise pill (`#31F1E8`, navy text); untreated teeth – grey number.
4. Upper row and lower row should share the same midline (between 11/21 and 41/31).

## 5. Checklist before release

- Render the 6 test plans from `TEST_krzyzowy_oferta_vs_system.jpg` and compare with the left-hand column: scale, tooth widths, gaps after missing teeth, implants without crowns sit lower, the full arch covers exactly 16–26.
- Check on a 520 px-wide page (mobile PDF) – the whole row must fit without scrolling.
